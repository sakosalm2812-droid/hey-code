# HEY — Non-Negotiable Rules

1. No MVP. No "light" version. No "almost done." Every piece ends 100% production-ready, tested, verified.
2. No fallbacks that weaken HEY. If a platform limits us, build the path — never shrink the feature.
3. One specialist = one job. Internally split like the human body: cells, muscles, blood — each activates only when needed, never all at once.
4. Three agent classes: always-active (research/monitoring/watchers), on-demand (only when invoked), user-created (born from a live need, kept only if the user saves it).
5. No terminal for OS actions. OS control is done by an agent that reads the screen, drives apps, and uses app adapters.
6. Cross-platform from day one. Windows, macOS, Linux, Android, iOS/iPadOS, web/PWA — same outcome level, different native implementations.
7. Closed source. Public launch after completion. Revenue from subscriptions. Users may run local models; they may not see or fork the source.
8. Every change is backed up and verified before it is called done. No "reload and check." No git clean. No git reset --hard.
9. Refined + detailed + short. Every line necessary. No filler. No overengineering.
10. Never hallucinate. If you have not seen the file, line, or output, say so. Do not invent.

## COMPLETION LADDER
DEFINED → IMPLEMENTED → CONNECTED → TESTED → VERIFIED → POLISHED → SHIPPABLE

UI-only = incomplete. Backend-only = incomplete. Undiscoverable = incomplete. Untested = incomplete. Unverified = incomplete.
